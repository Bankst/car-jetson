## Current state: AUDIO WORKING on all 8 TDM channels

RST# wire physically disconnected (board pullup keeps codec out of reset).

---

## 1. What's running and why

### Clocks
| Clock | Rate | Source | Notes |
|-------|------|--------|-------|
| PLLA_OUT0 | 49.152 MHz | PLLA VCO | BPMP won't let us change this |
| AUD_MCLK | 12.288 MHz | PLLA_OUT0 /4 | Set via DT `assigned-clock-rates` |
| I2S5 | 12.288 MHz | **BPMP debugfs override** | Normally 24.576 MHz (PLLA_OUT0/2). Set to 12.288 MHz by `i2s5-clock-fix.service` at boot via `mrq_rate_locked` |

**WHY the clock hack**: The BPMP firmware exposes I2S5 with `max_rate=24575992`. The kernel's `clk_set_rate(12288000)` rounds UP to the minimum available divider = PLLA_OUT0/2 = 24.576 MHz. This is 512×Fs, but CS42448 TDM requires BCLK = 256×Fs = 12.288 MHz. The `mrq_rate_locked` debugfs mechanism bypasses the BPMP max_rate constraint. Proper fix: modify BPMP DTB or find the correct PLL configuration.

### Kernel modules (hand-built, NOT from bitbake debs)

All three are on NVMe rootfs and survive reboot. They were cross-compiled via `scripts/kmod-build.sh` and pushed via SSH.

#### snd-soc-tegra210-i2s.ko
Source: `sound/soc/tegra/tegra210_i2s.c` (**NOT** `nvidia/sound/soc/tegra-alt/tegra210_i2s_alt.c` — the alt file is the NVIDIA source, but the build symlinks to a different copy)

Changes from stock:
1. **`nvidia,audio-channels` and `nvidia,sample-size` DT overrides in probe** — reads these properties and sets `audio_ch_override`, `client_ch_override`, `audio_fmt_override` at probe time. Without this, the C2C DPCM link negotiates 2ch/S16 and I2S5 generates wrong BCLK/LRCK.
2. **`bit_count` clamping** — changed `return -EINVAL` to `dev_warn + clamp to mask` when bit_count exceeds `I2S_TIMING_CH_BIT_CNT_MASK`. This prevents hw_params failure when BPMP gives a higher-than-requested clock rate.
3. **Debug print** in `set_timing_params` (can be removed).

#### snd-soc-tegra-utils.ko  
Source: `nvidia/sound/soc/tegra-alt/utils/tegra_asoc_dt_parser.c` (same file as source and build)

Changes from stock (also in patch 0005):
1. **DPCM flags on C2C links** — `no_pcm=1`, `dpcm_playback=1`, `dpcm_capture=0`. Without this, the C2C dai-link (i2s5_to_codec) never triggers hw_params on the codec or I2S5 DAP DAI. Audio data flows into the XBAR but I2S5 clocks never start.
2. **`asoc_simple_card_canonicalize_dailink`** — propagates `dai_fmt` (DSP-A + CBS_CFS) from the DT to the DAI link.
3. **`ignore_pmdown_time=1`** — matches PCM_LINK behavior.

Note: `dpcm_capture=0` — setting capture=1 caused the I2S5 to double the frame (TX+RX), though this theory was not conclusively proven. With capture=0, only playback triggers.

#### snd-soc-cs42xx8.ko
Source: `sound/soc/codecs/cs42xx8.c`

Changes from stock (also in patches 0004 + 0006):
1. **`set_dai_sysclk` guard** — ignores freq < 1 MHz. The Tegra machine driver's SFC init passes the sample rate (e.g. 48000) as sysclk, clobbering the real MCLK rate cached from `clk_get_rate()`.
2. **`DIV_ROUND_CLOSEST`** for MCLK/Fs ratio — Tegra PLLA produces 12287996 Hz, not exactly 12288000. Integer truncation gives 255 (rejected); rounding gives 256 (valid).
3. **`intf_val` re-apply in hw_params** — `set_dai_fmt` writes the INTF register (TDM format) via regmap, but this can be lost if the codec is runtime-suspended at the time. Saving the value and re-applying in `hw_params` ensures it reaches hardware.
4. **`msleep(5)` in probe** between reset assert and de-assert — CS42448 datasheet requires min 1ms RST# low pulse.

### DTB (on device at /boot/devicetree/tegra194-p3668-a203.dtb)

Built from `meta-seeed-jetson/recipes-bsp/seeed-a203-devicetree/custom/cs42448.dtsi`, then further patched via `fdtput` on device. The bitbake-built DTB and the on-device DTB may differ in `assigned-clock-rates` values (fdtput changed them).

Key DT nodes:
- `&tegra_i2s5`: `nvidia,audio-channels=<8>`, `nvidia,sample-size=<32>` — read by the patched I2S driver
- `&i2s5_to_codec`: `format="dsp_a"`, `bitclock-master`, `frame-master` — in NVIDIA's alt driver, `CBM_CFM` maps to `MASTER_EN=1` (Tegra drives BCLK/LRCK). This is inverted from standard ASoC convention.
- `&tegra_adsp_audio`: `status="disabled"` — ADSP's `component_open` returned -EPIPE for every PCM stream, blocking all DPCM BE activation
- `&tegra_sound`: `nvidia-audio-card,routing` connects CS42448 AOUT widgets to Speaker endpoints. Without this, DAPM never powers the codec path.
- `assigned-clock-rates = <12288000>, <12288000>` — PLLA_OUT0 + AUD_MCLK. BPMP ignores the PLLA_OUT0 rate (can't achieve it). AUD_MCLK does get set to 12.288 MHz.
- Pinmux: PQ.05 tristate + pull-up for RST# default-high

### Systemd services
- `i2s5-clock-fix.service` — oneshot, runs before pipewire. Sets I2S5 to 12.288 MHz via BPMP debugfs `mrq_rate_locked`.
- `snd_soc_cs42xx8_i2c` in `/etc/modules-load.d/banks-jetson-modules.conf` — autoloads the I2C binding module (udev can't match OF modalias to I2C module alias).

### PipeWire config
- `/etc/pipewire/pipewire.conf.d/20-cs42448-channel-map.conf` — creates `cs42448-sink` with `audio.position = [ FR FL RC LFE SR SL BR BL ]` to swap L/R per pair (board wires AOUT1=Jack R, AOUT2=Jack L).

```sh
ssh root@192.168.55.1 'cat > /etc/systemd/system/i2s5-clock-fix.service << "EOF"
[Unit]
Description=Set I2S5 clock to 12.288MHz via BPMP debugfs
Before=pipewire.service sound.target
```

## 4. Known issues / TODOs

1. **BPMP I2S5 clock** — `mrq_rate_locked` is a debugfs hack. Proper fix: modify BPMP DTB to change I2S5 max_rate, or find a PLL configuration that gives PLLA_OUT0 = 24.576 MHz without breaking AUD_MCLK.
2. **Patch 0007 targets wrong file** — `tegra210_i2s_alt.c` vs `tegra210_i2s.c`. Need to rewrite patch for the correct file.
3. **Patch 0005 has dpcm_capture=1** — should be 0. Update patch.
4. **RST# GPIO** — pin 29 wire disconnected. The Tegra GPIO driver claims PQ.05 and drives it low during probe, which asserts reset on the codec. Even with pinmux tristate + pullup in DT, the GPIO driver overrides it. Needs either: remove `reset-gpios` from DT, or fix the driver's GPIO release behavior.
5. **PipeWire channel remap + i2s5-clock-fix.service** — not in any Yocto recipe. Need to bake into the image.
6. **L/R swap** — hardware wiring on codec board (AOUT1=Jack R, AOUT2=Jack L). PipeWire remap handles it in software.
7. **Runtime PM** — codec suspends between streams. Next stream open triggers C2C hw_params which re-initializes everything. Works, but adds ~100ms latency on first audio after silence.
